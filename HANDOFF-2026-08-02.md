## 3. TRAPS — things that will bite silently

**The toolchain is a locally patched compiler that exists on ONE machine.** `nargo --version`
reports `1.0.0-beta.26+quid-icefix1`; `codegen-verifiers.sh` requires exactly that. **CI, or any
other developer, will fail the guard** — correctly, because they have stock beta.26. The marker
exists so this cannot happen invisibly. Stock binary: `~/.nargo/bin/nargo.beta26-release.bak`.
**The circuits still build on stock beta.26** — the accommodation was kept for exactly this.

**`bb` must be on PATH.** It is at `~/.bb/bb` (5.1.0). Without `export PATH="$HOME/.bb:$PATH"`,
`codegen-verifiers.sh` reports it missing and refuses.

**`aggregate_withdrawals` is DELIBERATELY ABSENT from `codegen-verifiers.sh` TARGETS**, so
`AggregationHonkVerifier.sol` is NOT regenerated by it. If the aggregation circuit ever changes,
nothing refreshes that verifier and the mismatch will surface as `SumcheckFailed()` far from the
cause. Same for the 83 `NoirRegisterIdentity_*.sol` passport verifiers (task 24).

**Regenerate only what changed.** Re-proving unchanged circuits is churn (ZK proofs are
non-deterministic) and one of them — `title_holder` — actually FAILS afterwards (task 30).

**`codegen-verifiers.sh` is step 4 of a 5-step pipeline.** Step 5 is
`tools/prove-escrow-fixtures.sh`, for the numbered `escrow_envelope0/1/2` fixtures
`IdentityRegistry.t.sol` loads. Skipping it produces exactly `SumcheckFailed()`. I skipped it once
and broke 18 tests.

**Nothing constructs a pool in production.** `DeployLib` holds salts only; all 5 construction
sites are tests. So `AGGREGATION_VERIFIER` has no deployment path yet — batching cannot be enabled
on a real deployment until something wires it.

## 4. FALSE SUCCESSES to watch for

**A background-task notification saying "exit code 0" is the WRAPPER's exit, not the command's.**
A `cargo test` run that aborted with exit 101 was reported as "completed (exit code 0)". Always
read the recorded `EXIT=`/`CARGO_EXIT=` line in the log. This nearly made me report a passing
regression suite that had crashed.

**`noirc_frontend`'s suite needs `RUST_MIN_STACK=134217728` on macOS** or
`tests::deeply_nested::deeply_nested_terms` overflows the stack in a release build — unrelated to
our patch, but it aborts the run and hides everything after it.

**A green wallet test file proves nothing if the module cannot load.** Six `pp/` modules were
unloadable by `node --test` (type-only imports as values, extensionless imports, a TS `enum`),
which is why that directory had zero tests for so long.

**`grep -c` and `\b` failed silently more than once here.** Two audit conclusions in this thread
were false positives from my own shell quoting (RootValidity "untested", a bogus dropped-test list).
Verify an empty result before believing it.
